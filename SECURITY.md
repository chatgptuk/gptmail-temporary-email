# Security Policy

## Reporting a vulnerability

Do not disclose a suspected vulnerability in a public GitHub issue. Send a concise report to **support@chatgpt.org.uk** with the subject `GPTMail security report`.

Include:

- the affected GPTMail page or feature;
- clear reproduction steps using synthetic data;
- the security impact;
- relevant browser and operating-system details;
- screenshots or logs only after removing addresses, message content, tokens, passwords, and personal data.

Do not access another person's inbox, retain private email, test with real credentials, send unsolicited mail, disrupt production traffic, or download more data than is necessary to demonstrate the issue.

## Public documentation repository

This repository contains product documentation rather than GPTMail's production infrastructure. Documentation mistakes and broken links can use the documentation feedback issue form. Vulnerabilities in the website, API, browser extension, domain authorization, or inbox access controls must be reported privately.

## Sensitive information

Never include any of the following in a report sent through a public channel:

- an active inbox address;
- a verification code or authentication link;
- a private-domain password;
- an API key or authorization token;
- email content or attachments;
- personal, financial, medical, or identity information.

If a credential has already been exposed, revoke or rotate it before sending the report.
